# packaging

Manifests for the package managers SDODS ships through. Two rules hold for everything here:

1. **Nothing in this directory is hand-edited.** Every file with a `.tmpl` suffix is a template;
   the rendered manifest beside it is generated by `bun run channels:sync`, which resolves the
   version and the SHA-256 from the real registry or the real release asset. A hand-typed checksum
   is a checksum nobody verified.
2. **A manifest is only published once the artifact it points at exists.** The npm package, the
   GHCR image and the `sdods-releases` release are three separate publishes with three separate
   owners. `channels:sync` refuses to mark a channel live until it can fetch the thing.

| Directory   | Manages                    | Installs                    | Depends on                          |
| ----------- | -------------------------- | --------------------------- | ----------------------------------- |
| `homebrew/` | `siri1410/homebrew-sdods`  | the CLI, against system Node| the npm tarball                      |
| `scoop/`    | `siri1410/scoop-sdods`     | the desktop app             | a published `desktop-v*` release     |
| `winget/`   | `microsoft/winget-pkgs` PR | the desktop app             | a published `desktop-v*` release     |
| `apt/`      | `sdods.com/apt`            | the desktop app             | a published `desktop-v*` release, the signing key |

npm and Docker have no manifest: they are published straight from `.github/workflows/release.yml`.

## Why the CLI and the desktop app split this way

Homebrew installs the CLI because a Homebrew user has a package manager and a shell, and wants the
`sdods` command. Scoop, winget and apt install the desktop app because their artifact is an
installer for a GUI application, which is exactly what those managers are built to place. They are
not two versions of one thing and their version numbers are independent — the CLI is `v*`, the
desktop app is `desktop-v*`.
