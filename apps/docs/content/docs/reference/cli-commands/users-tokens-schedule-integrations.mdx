## `users`

```text
sdods users create --username <name> --password <password> [--admin] [--role viewer|editor|admin] [--email <email>] [--org-owner]
sdods users list
sdods users set-role <username> <viewer|editor|admin>
sdods users grant <username> --org <slug> --role owner|admin|member
sdods users grant <username> --workspace <slug> --role admin|editor|viewer
sdods users deactivate <username>
```

`--admin` creates a platform admin who also becomes owner of every organization without an owner. `grant` manages membership roles; a user's effective role in a workspace is the stronger of the explicit workspace role and the one implied by the organization role (`member` → viewer, `admin`/`owner` → admin).

## `tokens`

```text
sdods tokens create --user <username> --name <label> [--scopes <list>] [--expires <days>]
sdods tokens list [--user <username>]
sdods tokens revoke <id>
```

Tokens are free, unlimited, scoped and revocable. `create` prints the value once; scopes default to every scope of the owner's role and may only be a subset of it. Tokens authenticate MCP over HTTP and CI ingest.

## `schedule`

```text
sdods schedule add -p <slug> --name <name> --cron <expr> [--tz <timezone>] [-e <env>] [-t <expr>] [-l <layer>]... [-b <browser>]...
                     [--process <name>] [--overlap skip|queue|cancel-previous] [--jitter <seconds>] [--notify <list>] [--disabled]
sdods schedule list [-p <slug>]
sdods schedule next --cron <expr> [--tz <timezone>] [--count <n>]
sdods schedule pause|resume|remove <name> -p <slug>
sdods schedule run-now <name> -p <slug>
sdods schedule history <name> -p <slug>
sdods schedule sync
sdods schedule install --target crontab|launchd|systemd|github [-p <slug>] [--out <dir>]
sdods schedule export
```

Schedules live in the project YAML (`schedules[]` and processes with a `schedule`) and in the database; `sync` mirrors YAML into the database, the server executes them, and `install` writes OS or GitHub Actions entries for server-less setups.

## `integrations`

```text
sdods integrations test -p <slug> [--provider github|jira]
sdods integrations notify --run-id <id> [-p <slug>] [--from-files] [--provider <name>] [--dry-run] [--report-url <url>] [--artifacts-dir <dir>]
sdods integrations sync -p <slug> [--provider <name>]
sdods integrations links -p <slug> [--provider <name>]
```

`notify` publishes a run to the enabled providers (GitHub check run and PR comment, GitHub or Jira issues deduplicated by scenario fingerprint); `--from-files` builds the summary from the run directory so it works without a database. `sync` scans features for `@jira:KEY` and `@github:N` tags, creates links and refreshes their status.
