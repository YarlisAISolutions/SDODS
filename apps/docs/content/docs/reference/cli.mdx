## Invocation

Inside the repository the command runs from source:

```bash
bun run sdods <command> [options]
```

After publishing, `npx -y @sdods/cli <command>` or a global install do the same.

## Global options

| Option          | Effect                                                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `--json`        | machine-readable output; errors become `{ "error": { code, message, hint, docsUrl } }` on stderr                                                |
| `-q, --quiet`   | errors only                                                                                                                                     |
| `--verbose`     | debug logging                                                                                                                                   |
| `--cwd <dir>`   | repository root; by default SDODS walks up from the current directory to find `sdods.workspace.yaml`, `sdods.config.ts` or a `projects/` folder |
| `--no-color`    | disable colours                                                                                                                                 |
| `-V, --version` | print the version                                                                                                                               |

Every flag has an `SDODS_*` environment equivalent, listed in [Environment variables](/docs/reference/environment-variables).

## Exit codes

| Code  | Meaning                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------------ |
| `0`   | success                                                                                                |
| `1`   | test failures, or a runtime error                                                                      |
| `2`   | configuration or usage error (unknown project, missing environment, invalid YAML, unresolved variable) |
| `3`   | lint errors                                                                                            |
| `130` | cancelled                                                                                              |
