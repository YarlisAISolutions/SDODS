Tools are grouped by capability (`sdods mcp --caps core,analyze,run,data,browser,agents,issues,schedules`; default `core,analyze,run,data,browser,schedules`). Access levels map to scopes: `read` needs the matching `*:read` scope, `run` needs `runs:write`, `write` produces proposals and needs `features:write`. Print the live catalogue with `sdods mcp --list-tools`.

Prompts: `sdods-plan`, `sdods-generate`, `sdods-heal`, `sdods-upgrade`, `sdods-review`.

## Browser tools

SDODS wraps **every** tool of the Playwright MCP server that ships inside the pinned Playwright — 42 of them — as `browser_*`, plus three of its own for session lifecycle.

They are the upstream tools, argument for argument. What the wrapper adds is the context an ungoverned browser has no way to know:

- **Bound to a project and environment.** The session carries the project's `testIdAttribute`, the environment's locale, timezone, headers and credentials, and the viewport from `screenshots.viewport`. A snapshot taken through `browser_snapshot` refers to elements by the same test-id attribute the page objects use.
- **Logged in as a role.** `browser_session_open` with `role` reuses the storage state `sdods auth capture` wrote for that `@user:<role>`. It will not capture one for you — that drives a real login flow.
- **Artifacts in the run.** Screenshots, PDFs, traces and videos land in `.sdods/runs/<runId>/browser/<sessionId>/`, next to everything else about that run.
- **Credentials redacted.** `authorization`, `cookie`, `set-cookie` and API-key headers are masked in `browser_network_request` output before it reaches a transcript.
- **Refusable.** `browser:read` lets a viewer look; acting needs `browser:write`. `browser_evaluate` and `browser_run_code_unsafe` run caller-supplied code — upstream calls the latter RCE-equivalent — so they need `browser:admin` **and** `SDODS_BROWSER_ALLOW_UNSAFE=1`, and are off by default.

```
browser_session_open { project: "demo-shop", env: "staging", browser: "edge", role: "standard" }
browser_navigate     { url: "/inventory.html" }
browser_snapshot     {}
browser_session_close {}
```

Calling an action tool without opening a session first opens a default one from the server's `--project`, so the common case is one call. Observe tools do not — they return `BROWSER_NO_SESSION` rather than starting a browser, because `browser:read` is a scope every viewer holds.

`browser_session_close` ends the session and stops the browser; upstream's `browser_close` closes the page and leaves the session up. Sessions are also reaped when idle, and belong to the connection that opened them, so one HTTP principal cannot drive another's logged-in browser.

<Callout>
  The extra Playwright capability packs are per session: pass `caps: ["vision", "pdf", "devtools"]`
  to `browser_session_open` for coordinate-based mouse input, `browser_pdf_save`, and
  tracing/video/highlighting.
</Callout>

The raw upstream server is no longer registered alongside. `sdods mcp install --with-playwright` still adds it for anyone who wants it directly, with none of the above.
