### Canvas

Selectors for the [canvas steps](/docs/reference/step-library#canvas-steps). The defaults match the DOM React Flow renders; override only the keys your editor does differently. Each value is a CSS selector template: `{id}`, `{handle}`, `{source}`, `{target}`, `{field}` and `{badge}` are replaced by the step argument, escaped for a quoted CSS string, so keep them inside quotes. `{testIdAttribute}` is replaced by the project's `testIdAttribute`. A template without its required placeholder, or with an unknown one, fails config validation.

A workflow builder that marks its blocks with its own attributes overrides only those keys:

```yaml
canvas:
  field: '[data-subblock-id="{field}"]'
  badge: '[{testIdAttribute}="block-{badge}"]'
```

With that block, `Then the node "agent-1" should show the "error-badge" badge` looks for `[data-testid="block-error-badge"]` inside the node `.react-flow__node[data-id="agent-1"]`.

Load profiles are not part of this file: each lives in `projects/<slug>/load/<name>.yaml` and runs with [`sdods load`](/docs/reference/cli-commands/load). The field reference is in [Load testing](/docs/guides/load-testing).

### Setup scenarios

`setup: { tags: '@setup' }` runs the scenarios matching `tags` before everything else in the run and
skips the rest when one of them fails, instead of letting every scenario fail on its own against a
broken environment or a login that does not work.

- Every run target gets a companion target named `<target>--setup` (for example
  `demo-shop--ui--chromium--setup`, `demo-shop--api--setup`) that runs that layer's setup scenarios in
  the same browser, and the target depends on it (Playwright project `dependencies`). When a setup
  scenario fails, Playwright reports the target's scenarios as "did not run".
- Setup scenarios are selected by `setup.tags` alone: `--tags`, `--grep`, `--feature` and `--module`
  narrow the target's own scenarios, never the setup tier. They are excluded from the target, so they
  run once.
- Setup scenarios are ordinary scenarios: they still carry one layer tag and one suite tag. Declare
  the tag under `tags.extra` so lint does not warn about it.
- A process can use other setup tags (`setup: { tags: '@probe or @auth' }`) or none (`setup: false`).
- Recorded specs (`layer: recorded`) have no tags and get no setup tier.

```yaml
tags: { extra: [setup] }
setup: { tags: '@setup' }
processes:
  - { name: release-gate, fullyParallel: false }
  - { name: quick, setup: false }
```
